# 2026-06-12 작업 로그

## Today

- 국내 의류 B2B 서비스 흐름에 맞춰 상품 옵션, 장바구니, 주문, 견적서, 주문 진행 이력 구조를 재설계했다.
- 여러 셀러의 상품은 한 장바구니에 담되, 주문 생성 시에는 셀러별로 분리하는 기준을 세웠다.
- `orders`와 `order_items`를 분리하고 주문 당시 상품명, 옵션, 가격을 스냅샷으로 저장하도록 정리했다.
- Checkout은 별도 테이블이 아니라 장바구니와 배송지 정보를 조합해 주문을 생성하는 Request DTO로 보았다.
- 실제 등록 상품이 없어도 작성할 수 있도록 견적서가 상품 테이블에 과도하게 의존하지 않게 설계했다.

## Learned

- DB 설계는 테이블을 나누는 작업이 아니라 데이터의 흐름과 각 테이블의 책임을 정하는 아키텍처 설계에 가깝다.
- 주문처럼 과거 시점의 정보가 중요한 데이터는 현재 상품 정보만 참조하지 않고 스냅샷을 함께 보존해야 한다.
- 현재 상태와 상태 변경 이력을 분리하면 조회는 단순하게 유지하면서도 전체 진행 과정을 추적할 수 있다.
- 인덱스는 모든 FK에 습관적으로 추가하기보다 실제 조회 조건과 정렬 패턴을 기준으로 결정해야 한다.
