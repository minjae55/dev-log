## What I Focus On

- 기능을 연결하는 데서 끝내지 않고 요청이 인증, 서비스와 DB를 거쳐 응답으로 돌아오는 전체 흐름을 이해하려고 합니다.
- 새로운 기술을 적용할 때 사용법만 익히기보다 현재 문제에 왜 필요한지와 다른 선택지는 무엇인지 함께 고민합니다.
- 오류가 발생하면 보이는 메시지만 수정하지 않고 요청 데이터, 실행 흐름과 쿼리를 확인해 실제 원인을 찾습니다.
- 구현 과정에서 내린 판단과 시행착오를 기록하고, 다시 설명할 수 있는 지식으로 정리합니다.

## 기록 방식

- **프로젝트 README**: 프로젝트의 목적, 현재 상태, 핵심 기능과 설계 판단을 요약합니다.
- **개발일지**: 날짜별 구현 내용, 당시의 판단, 문제 해결 과정과 다음 작업을 기록합니다.
- **기술 블로그**: 개발 중 발견한 질문을 골라 개념과 선택의 근거를 더 깊게 정리합니다.
