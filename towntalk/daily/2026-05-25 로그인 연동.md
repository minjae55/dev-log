## Learned
- React + JSON API 로그인에서는 Spring Security `formLogin`보다 `AuthenticationManager`를 직접 사용하는 방식이 더 자연스럽다.
- Spring Security의 `username`은 우리 서비스 기준으로 `loginId`에 해당하므로 용어를 맞춰서 이해해야 한다.
- Spring Security `formLogin`과 React JSON API 로그인 흐름 차이를 트러블슈팅 글로 복습했다.
  - https://min-soon.tistory.com/66
- 비밀번호는 저장할 때 해시하고, 로그인 검증 시 `PasswordEncoder`가 원문 비밀번호와 해시된 비밀번호를 비교한다.

## Troubleshooting
- React + JSON API 로그인 방식에서 Spring Security `formLogin`을 그대로 쓰기 어렵다는 점을 정리했다.
- 로그인 실패 메시지가 프론트에 제대로 표시되지 않는 원인을 예외 응답 구조와 프론트 에러 처리 흐름에서 확인했다.

## Blocker
- 로그인 검증을 Spring Security에 맡길 때 `AuthenticationManager`, `UserDetailsService`, `UsernameNotFoundException`의 역할이 헷갈렸다.
- 로고 이미지를 바꿔도 바로 반영되지 않아 브라우저/CDN 캐시 가능성을 확인했다.
- 메인 화면 색상과 분위기를 잡는 과정에서 여러 색상 조합을 시도했다.
