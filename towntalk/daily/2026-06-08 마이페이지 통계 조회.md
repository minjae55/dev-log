# 2026-06-08 작업 로그

## Today
- Backend: 마이페이지에서 로그인 사용자의 기본 정보와 작성 글 수, 작성 댓글 수, 받은 좋아요 수를 조회할 수 있도록 `UserMyPage` 응답 DTO와 `/api/user/myPage` API를 추가하고, QueryDSL `JPAExpressions`를 사용해 관련 테이블의 집계 값을 조회하도록 구성했다.
- Frontend: 마이페이지 화면에서 기존 더미 통계 값을 제거하고 `/api/user/myPage` 응답을 기준으로 닉네임, 로그인 ID, 레벨, 작성 글 수, 댓글 수, 받은 좋아요 수를 렌더링하도록 연결했다.

## Learned
- 작성 글 수와 댓글 수는 각각 `posts`, `comments` 테이블에서 바로 count할 수 있지만, 받은 좋아요 수는 `likes` 테이블만 보면 안 되고 내가 작성한 게시글과 연결해서 계산해야 한다.
- `users.total_likes` 같은 컬럼은 빠른 조회를 위한 counter cache로 사용할 수 있지만, 좋아요 저장/취소 시 값이 틀어지지 않게 동기화해야 하므로 현재 단계에서는 `likes` 테이블을 기준으로 count하는 방식이 더 단순하고 안전하다.

## Troubleshooting
- 마이페이지 조회 API를 추가했는데 `/api/user/myPage` 요청이 `UserController`로 매핑되지 않고 정적 리소스 핸들러로 빠지는 문제가 있었다.
  - 원인은 실행 중인 Spring Boot 서버에 최신 컨트롤러 코드가 반영되지 않은 상태였기 때문이다.
  - 서버를 재시작한 뒤 `@GetMapping("/myPage")` 매핑이 정상 반영되어 API가 호출됐다.
- 받은 좋아요 수를 `user.totalLikes`로 가져올지, `JPAExpressions`로 실시간 집계할지 고민했다.
  - `user.totalLikes`는 조회는 빠르지만 좋아요 저장/취소 시 별도로 증가/감소 처리를 해야 한다.
  - 현재는 데이터 정합성을 우선해 `likes`와 `posts`를 연결한 count 쿼리로 받은 좋아요 수를 계산하는 방향을 선택했다.
