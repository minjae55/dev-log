# 2026-06-02 작업 로그

## Today
- Backend: QueryDSL로 메인 화면에 사용할 최신 게시글 3개 조회 API를 추가했다.
- Frontend: 메인 화면의 하드코딩 게시글을 제거해 최신 게시글 API 응답으로 렌더링하고, 글쓰기 화면에서 `@Valid` 실패 응답을 필드별 에러 메시지로 표시하도록 수정했다.

## Learned
- QueryDSL 조회는 `select -> from -> orderBy -> limit -> fetch` 흐름으로 이해하면 SQL과 비슷하게 따라갈 수 있다.
- DTO 조회는 엔티티 전체를 가져오기보다 `Projections.constructor`로 필요한 필드만 내려주는 방식이 깔끔하다.

## Troubleshooting
- QueryDSL을 처음 적용하면서 Repository, QueryRepository, DTO projection의 역할을 구분하는 데 시간이 걸렸다.
- 조회 API는 단순히 데이터를 꺼내는 것뿐 아니라, 프론트 화면에서 바로 사용할 수 있는 응답 형태까지 함께 맞춰야 했다.
  - https://min-soon.tistory.com/72

## Blocker
- `createdAt` 필드가 아직 엔티티에 매핑되어 있지 않아, 최신순 정렬을 우선 `id desc` 기준으로 처리했다.
