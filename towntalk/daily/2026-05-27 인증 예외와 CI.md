## Learned
- Spring Security 필터 단계의 인증 실패는 `GlobalExceptionHandler`가 아니라 `AuthenticationEntryPoint`에서 처리하는 것이 자연스럽다.
- `AuthenticationManager`, `UserDetailsService`, `SecurityContextHolder`의 역할을 구분하며 로그인 인증 흐름을 복습했다.
- CI는 로컬에서만 되는 코드인지, GitHub의 깨끗한 환경에서도 빌드되는 코드인지 확인하는 장치다.
- Refresh Token은 브라우저에서는 HttpOnly Cookie로 안전하게 보관하고, 서버에서는 Redis로 유효성을 관리할 수 있다.
- `JwtProvider` 테스트를 통해 Mockito가 필요한 경우와 직접 객체를 생성하는 경우를 구분했다.

## Troubleshooting

## Blocker
- `AuthenticationManager`, `SecurityContextHolder`, `Authentication` 객체와 Access Token의 관계를 구분하는 데 시간이 걸렸다.
- 테스트를 클래스 기준이 아니라 시나리오 기준으로 작성한다는 기준을 잡는 데 헷갈림이 있었다.
- GitHub Actions에서 원격 커밋에 빠진 파일 때문에 프론트 빌드가 실패해 커밋 범위 확인이 필요했다.
