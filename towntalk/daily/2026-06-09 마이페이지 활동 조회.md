# 2026-06-09 작업 로그

## Today
- Backend: 게시글 조회수 기능을 위해 `posts.view_count`를 `Post` 엔티티와 게시글 목록/상세 응답 DTO에 반영하고, QueryDSL 조회 projection에서 `viewCount`가 내려오도록 연결했다. 마이페이지 응답은 프로필 요약, 내가 쓴 게시글 목록, 내가 쓴 댓글 목록 구조로 확장했으며, `MyPageService`에서 `UserRepository`, `PostRepository`, `CommentRepository`를 조합해 화면에 필요한 데이터를 한 번에 반환하도록 구성했다. 내 글 목록에는 제목, 내용, 작성일, 댓글 수, 좋아요 수, 조회수를 포함하고, 내 댓글 목록에는 게시글 id/제목, 댓글 내용, 익명 여부, 작성일을 포함하도록 DTO와 QueryDSL 조회를 추가했다.
- Frontend: 메인 피드와 게시글 상세 화면에 조회수를 표시하도록 연결했다. 마이페이지에서는 더미 게시글 데이터를 제거하고 `/api/user/myPage` 응답 기반으로 내 글/내 댓글 탭을 렌더링하도록 변경했으며, 각 카드 클릭 시 게시글 상세 페이지로 이동하도록 처리했다. 목록 영역은 높이를 제한해 내부 스크롤로 탐색할 수 있게 했다.

## Learned
- 마이페이지처럼 여러 도메인의 데이터를 모아 보여주는 화면은 Controller에서 여러 Service를 직접 호출하기보다, 마이페이지 전용 Service가 Repository들을 조합해 응답 DTO를 만드는 구조가 더 깔끔하다.
- 화면 전용 DTO는 기존 DTO와 필드가 일부 겹치더라도 역할이 다르면 분리하는 편이 변경에 강하다. `ReadPost`와 `MyPagePost`는 비슷한 필드를 갖지만, 하나는 게시글 목록 응답이고 다른 하나는 마이페이지 내 활동 카드용이므로 분리해도 자연스럽다.
- 현재 단계에서 내 글/내 댓글 전체를 한 번에 받아온 뒤 프론트에서 목록 영역에 스크롤을 주는 방식은 구현이 단순하다. 데이터가 많아지면 `/myPage/posts?page=&size=`, `/myPage/comments?page=&size=` 같은 서버 페이징으로 확장하는 것이 좋다.

## Troubleshooting
- 마이페이지 조회 로직을 어디에 둘지 고민했다.
  - Controller에서 `UserService`, `PostService`, `CommentService`를 각각 호출하면 Controller가 화면 조립 책임까지 갖게 된다.
  - 기존 `UserService`에 계속 추가하면 사용자 가입/인증/프로필 흐름과 마이페이지 조회 흐름이 섞여 Service가 커질 수 있다.
  - 최종적으로 `MyPageService`를 두고, 이 Service가 `UserRepository`, `PostRepository`, `CommentRepository`를 통해 마이페이지 응답을 조립하도록 정리했다.
- `MyPagePost`를 새로 만들지 `ReadPost`를 재사용할지 고민했다.
  - 두 DTO 모두 제목, 내용, 작성일, 댓글 수, 좋아요 수, 조회수처럼 겹치는 필드가 있다.
  - 하지만 `ReadPost`는 게시글 목록 API의 응답이고, `MyPagePost`는 마이페이지 내 글 카드의 응답이므로 변경 방향이 달라질 수 있다.
  - 마이페이지에서는 작성자 닉네임이나 카테고리보다 내 활동 요약에 필요한 값이 중요하므로, 화면 의미에 맞춰 `MyPagePost`를 별도 DTO로 유지했다.
- 마이페이지 댓글 DTO를 어느 정도까지 포함할지 고민했다.
  - 처음에는 댓글 개수만 있으면 충분하다고 판단했지만, 내 댓글 탭에서 댓글 목록을 보여주고 상세 페이지로 이동하려면 `postId`가 필요했다.
  - 사용자가 어떤 글에 단 댓글인지 알 수 있도록 `postTitle`도 함께 내려주기로 했다.
  - 최종적으로 `MyPageComment(postId, postTitle, content, anonymous, createdAt)` 구조로 정리했다.
- `post.viewCount`가 QueryRepository에서 보이지 않는 문제가 있었다.
  - DB 컬럼과 엔티티 필드는 추가됐지만 QueryDSL Q클래스가 재생성되지 않아 `QPost`에 `viewCount`가 없는 상태였다.
  - Gradle 실행 JVM이 Java 8로 잡혀 있어 annotation processor가 정상 실행되지 않았고, 사용자 환경 변수의 `JAVA_HOME`과 `Path`를 JDK 21로 수정해 해결했다.
- 마이페이지 응답 DTO를 class로 만들었을 때 JSON 응답이 비어 나갈 수 있는 문제가 있었다.
  - private 필드와 생성자만 있고 getter가 없으면 Jackson이 응답 필드를 직렬화하지 못할 수 있다.

## Blocker
- `frontend/package-lock.json`에 기능 변경과 직접 관련 없는 의존성 lock 변경이 남아 있어 커밋 대상에서 제외해야 한다.
