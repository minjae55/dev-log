# 2026-06-01 작업 로그

## Today
- Backend: 로그아웃 API, Refresh Token 쿠키 기반 Access Token 재발급 API, 게시글 작성 요청 검증을 추가했다.
- Frontend: `401` 응답 시 `/api/auth/reissue`를 호출하고, 새 Access Token으로 원래 요청을 재시도하도록 처리했다.

## Learned
- Access Token은 프론트에서 삭제하고, Refresh Token은 백엔드에서 Redis 삭제와 Cookie 만료로 처리해야 한다.
- 토큰 재발급은 Access Token이 아니라 Refresh Token 쿠키를 기준으로 동작해야 한다.
- `Authentication`은 Access Token 검증 후 만들어지는 인증 객체이므로, Access Token이 만료된 재발급 API에서는 기준으로 쓰기 어렵다.

## Troubleshooting
- Access Token이 만료되거나 삭제된 뒤에도 Refresh Token 쿠키가 유효하면 새 Access Token을 발급받고 원래 요청을 재시도하는 흐름을 확인했다.
  - https://min-soon.tistory.com/71

## Blocker
- Refresh Token은 HttpOnly Cookie라 브라우저 콘솔에서 직접 확인할 수 없어 Application 탭과 Network 탭을 함께 봐야 했다.
- 재발급 API에서 `Authentication`을 사용할지, Cookie의 Refresh Token을 사용할지 흐름을 구분하는 데 시간이 걸렸다.
