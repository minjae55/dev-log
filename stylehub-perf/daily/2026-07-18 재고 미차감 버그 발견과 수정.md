## Today

- 주문 생성처럼 반드시 실행되는 핵심 플로우에서 비즈니스 로직 누락이 없는지 확인하다가, 주문 생성 시 실제로 재고(`ProductOption.stockQuantity`)가 차감되지 않는 것을 확인했다.
- `ProductOptionRepository`가 `JpaRepository`만 상속한 완전히 빈 인터페이스였고, `BuyerOrderService`를 포함한 어떤 코드에서도 재고를 차감하는 로직을 찾을 수 없었다.
- 재고 10개짜리 테스트 상품 옵션을 만들고, k6로 20명이 동시에 1개씩 주문하는 재현 시나리오(`oversell-test.js`)를 작성해 실행했다. 20명 전원이 200으로 성공해, 재고 10개가 20개(200%) 팔리는 걸 확인했다.
- `ProductOptionRepository`에 `UPDATE ... SET stock_quantity = stock_quantity - :quantity WHERE stock_quantity >= :quantity` 형태의 원자적 조건부 UPDATE(`decreaseStock`)를 추가하고, `BuyerOrderService.createOrder()`에서 주문 생성 시 호출해 차감 실패 시 `OUT_OF_STOCK`(400)을 던지도록 수정했다.
- 같은 20명 동시 주문 시나리오를 재고/카트를 복구한 뒤 다시 실행했다. 이번엔 정확히 10명만 성공(200), 나머지 10명은 재고 부족으로 정상 거부(400)됐고, SQL로 재고가 10→0, 판매량이 정확히 10으로 떨어진 걸 확인했다.

## Learned

- 원자적 조건부 UPDATE(`WHERE stock_quantity >= :quantity`)는 애플리케이션 코드에서 "조회 후 판단"하는 대신 DB 행 잠금에 위임하는 방식이라, 동시 요청 상황에서도 별도의 락 없이 초과 판매를 막아준다.

## Troubleshooting

- 재고 미차감 발견 → 수정 후 재검증을 위해 재현 스크립트를 다시 돌렸는데, 20명 전원이 "카트 아이템 없음"으로 실패했다. 원인은 직전(버그가 있던) 테스트에서 성공한 주문들이 해당 카트 아이템을 이미 다 삭제했기 때문. 재고 자체는 옛 코드가 차감하지 않아 그대로 10으로 남아있었으므로, 전체 시드를 다시 만들 필요 없이 테스트 옵션에 걸린 카트 아이템만 재삽입하고 이전 주문 기록만 정리해서 재현 환경을 복구했다.
