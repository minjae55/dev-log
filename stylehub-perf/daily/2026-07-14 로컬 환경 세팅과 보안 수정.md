## Today

- StyleHub B2B 개인 fork 저장소(`stylehub-perf`)의 로컬 개발 환경을 다시 점검했다.
- 프론트엔드 `npm install`이 되어 있지 않아 `vite` 명령어가 실행되지 않던 문제를 해결했다.
- `.gitignore`를 정리하다가, 실제 시크릿(OAuth/Toss/JWT/Supabase 키 등)이 담긴 `application-local.yaml`이 `.yml` 확장자로만 등록되어 있어 무시되지 않고 있던 걸 발견해서 수정했다.
- gitignore 수정 커밋을 main과 cmj-dev 양쪽에 반영했는데, cmj-dev에는 아직 정리되지 않은 다른 작업(order/quote 도메인 개선)이 많이 쌓여있어서, 전체 브랜치를 병합하는 대신 `git cherry-pick`으로 gitignore 수정 커밋 하나만 main에 옮겼다.
- `.github/PULL_REQUEST_TEMPLATE.md`가 팀 저장소에서 fork될 때 그대로 따라온 걸 발견하고, PR 생성 시 이 내용이 자동으로 채워지는 이유를 확인했다.

## Learned

- `.gitignore` 패턴은 문자열을 정확히 비교하기 때문에, 확장자 하나(`yml` vs `yaml`)만 달라도 매칭이 안 된다.
- `git status`에 파일이 `??`(untracked)로 뜬다는 건 gitignore가 그 파일을 못 잡고 있다는 신호다.
- 브랜치 전체를 병합하지 않고 특정 커밋 하나만 다른 브랜치에 옮기고 싶을 땐 `git cherry-pick`을 쓰면 된다.

## Troubleshooting

- `application-local.yaml`이 gitignore에 안 걸려서 시크릿이 그대로 커밋될 뻔한 걸 push 직전에 발견해서 수정했다.
- main과 cmj-dev가 같은 파일(order/quote 관련 도메인 코드)을 서로 다르게 수정해둔 상태라, 전체 병합 시 충돌이 예상되어 지금 당장은 gitignore 수정만 cherry-pick으로 분리해서 처리했다.
