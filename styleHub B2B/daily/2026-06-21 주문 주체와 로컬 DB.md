> 관련 글: [seller_id 하나로는 부족했다: B2B 주문의 판매 주체를 다시 설계한 과정](https://min-soon.tistory.com/91)

## Today

- 장바구니 상품을 판매 회사별로 묶어 주문을 생성하는 흐름을 설계했다.
- 주문의 판매 주체를 개별 사용자에서 판매 회사로 변경하고 주문 당시 회사명을 스냅샷으로 보존하도록 수정했다.
- 하나의 주문에 여러 담당자의 상품이 포함될 수 있어 상품별 담당자는 `order_items.assigned_user_id`로 분리했다.
- 공용 DB에 영향을 주지 않고 엔티티 변경을 검증할 수 있도록 Docker MySQL과 로컬 Spring Profile을 구성했다.

## Learned

- B2B 주문의 거래 주체인 회사와 실제 상품 담당자인 사용자는 서로 다른 책임으로 관리해야 한다.
- 엔티티 코드 변경과 공용 DB 스키마 반영은 각각 검증하고 팀원과 협의한 뒤 적용해야 한다.

## Troubleshooting

- 공용 DB의 `ddl-auto: update` 환경에서 엔티티를 변경하면 합의되지 않은 컬럼이 바로 반영될 수 있어 개인 로컬 DB를 분리했다.
- Docker MySQL 연결 시 `Public Key Retrieval is not allowed` 오류가 발생해 JDBC URL에 `allowPublicKeyRetrieval=true`를 추가했다.
