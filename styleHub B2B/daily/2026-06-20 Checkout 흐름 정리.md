## Today

- Checkout 흐름을 다시 처음부터 정리하면서 요청값과 Repository 조회 역할을 구분해 봤다.
- Checkout API가 왜 `GET`이 아니라 `POST`이고, 왜 Request Body로 값을 받는지 다시 확인했다.

## Learned

- `List<@NotNull @Positive Integer>`는 리스트 자체가 아니라 리스트 안의 각 원소를 검증하는 방식이다.
- Checkout 미리보기는 단순 조회처럼 보여도 선택한 장바구니 항목 조합을 서버에 보내 계산하는 요청이기 때문에 `POST`가 더 자연스럽다.
- 장바구니 단계의 검증과 Checkout 단계의 검증은 겹쳐 보여도 역할이 다르다.

## Troubleshooting

- 처음에는 MOQ, 재고, 샘플 수량 검증이 장바구니에서만 처리되어야 하는 것 아닌지 헷갈렸다.
- 정리해보니 장바구니에서는 사용자의 입력을 1차로 막고, Checkout에서는 재고나 활성 상태처럼 결제 직전에 다시 확인해야 하는 값을 최종 검증하는 구조가 더 맞았다.
