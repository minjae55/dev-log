# 2026-06-17 작업 로그

> 관련 글: [FK와 객체 연관관계, JPA 지연 로딩 이해](https://min-soon.tistory.com/86)

## Today

- `CartItem`이 `userId` 대신 `User` 객체를 참조하는 이유를 정리했다.
- DB의 FK와 JPA 객체 연관관계, `LAZY`와 `EAGER`의 조회 시점 차이를 확인했다.
- 연관 엔티티 접근이 반복될 때 발생할 수 있는 N+1 문제도 살펴봤다.

## Learned

- DB의 `user_id` FK를 JPA는 `User` 객체 연관관계로 추상화한다.
- `LAZY`는 프록시를 두고 실제 값이 필요할 때 조회하므로 객체 참조가 곧 즉시 전체 조회를 의미하지 않는다.
- DTO 변환 시에는 영속성 컨텍스트와 트랜잭션 범위를 함께 고려해야 한다.

## Troubleshooting

- 처음에는 `User user`를 선언하면 사용자 전체 데이터가 항상 조회된다고 생각했다.
- 실제로는 프록시가 조회를 미룬다는 점을 확인하며 객체 연관관계와 조회 전략을 구분했다.
