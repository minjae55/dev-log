## Today

- 주문 목록 API가 빈 배열을 반환해도 예시 주문이 표시되는 문제를 수정했다.
- 실제 주문이 없으면 빈 주문 상태를 표시하고, 조회 실패 시에는 오류 안내만 표시하도록 변경했다.
- 로딩, 조회 실패, 실제 주문 0건, 검색 결과 0건의 화면 상태를 구분했다.
- 개발용 예시 주문은 일반 화면의 fallback에서 제거하고 `/orders?demo=orders` 경로에서만 확인하도록 분리했다.

## Learned

- 빈 배열은 조회 실패가 아니라 데이터가 없는 정상 응답이다.
- 로딩, 오류, 빈 데이터와 정상 데이터를 하나의 조건으로 처리하면 서로 다른 안내 화면이 동시에 노출될 수 있다.
- 개발용 예시 데이터는 실제 서비스 흐름의 fallback으로 사용하지 않고 명시적인 개발 경로로 격리해야 한다.

## Troubleshooting

- 주문이 없는 사용자에게 실제로 생성하지 않은 예시 주문이 표시됐다.
- `nextOrders.length > 0 ? nextOrders : exampleOrders` 조건이 정상적인 빈 배열까지 fallback 대상으로 처리한 것이 원인이었다.
- API 응답이 빈 배열이면 주문 상태를 그대로 빈 배열로 유지하도록 수정했다.
- `isLoading`과 `loadError`가 없을 때만 빈 상태를 표시해 로딩·오류 안내와 빈 화면이 동시에 나타나지 않도록 했다.
- 전체 주문이 0건인 경우와 검색·필터 결과만 0건인 경우의 문구를 구분했다.
